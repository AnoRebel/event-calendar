`EventCalendar` is a **controlled** component: it renders the `events` you pass and emits what the user wants to
change. It never fetches or stores anything itself, so it fits any backend.

```vue
<EventCalendar
  v-model:view="view"
  v-model:date="date"
  :events="events"
  :loading="isLoading"
  :features="{ recurringEvents: true }"
  class="h-[80vh]"
  @event-add="create"
  @event-update="save"
  @event-delete="remove"
/>
```

## Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `events` | `CalendarEvent[]` | — | The events to show. Dates may be `Date` objects or ISO strings. |
| `initialView` | `'month' \| 'week' \| 'day' \| 'agenda'` | `'month'` | Starting view when `v-model:view` isn't used. |
| `loading` | `boolean` | `false` | Shows a progress bar over the grid. |
| `features.recurringEvents` | `boolean` | `false` | Shows the repeat options in the event dialog. |

## Models

| Model | Type | Description |
| --- | --- | --- |
| `v-model:view` | `ViewMode` | The current view. Bind it to keep the view in the URL or in storage. |
| `v-model:date` | `Date` | The date the view is showing. |

## Events

| Event | Payload | When |
| --- | --- | --- |
| `event-add` | `CalendarEvent` | The user saved a new event. Its `id` is a client-side UUID; replace it with your server's id. |
| `event-update` | `CalendarEvent` | An edit was saved, or an event was moved or resized. Fired **once per gesture**, on release. |
| `event-delete` | `string` (id) | The user confirmed a delete. |

## Slots and methods

- `#header-actions` — extra controls at the end of the toolbar (for example a theme switch).
- `openAddModal(date?: Date)` — opens the new-event dialog, through a template ref.

## The event shape

```ts
interface CalendarEvent {
  id: string
  title: string
  description?: string
  startDate: Date
  endDate: Date
  allDay?: boolean
  color?: "sky" | "amber" | "violet" | "rose" | "emerald" | "orange"
  location?: string
  status?: "confirmed" | "tentative" | "cancelled" // "past" is derived when an event has ended
  timezone?: string // IANA zone the times were entered in, e.g. "Europe/Berlin"
  isRecurring?: boolean
  recurringPattern?: RecurringPattern
}
```

Start and end are absolute instants. The grid lays events out in the viewer's local time; `timezone` records the zone
the times were typed in, so the dialog can show and edit them in that zone.

## Interaction

| Action | Mouse | Touch |
| --- | --- | --- |
| Create | Click an empty slot (week/day) or a day (month), or **Add event** | Tap a slot, or **+** |
| Edit | Click the event | Tap the event |
| Move | Drag the event | Press and hold, then drag |
| Change length | Drag the top or bottom edge | Press and hold an edge, then drag |
| Cancel a drag | `Esc` | Drag back to where it started |
| Change period | ← / → buttons | Swipe left or right (month, day, agenda) |

Moving and resizing snap to 15 minutes. While dragging, overlapping events re-flow side by side, and the grid scrolls
when you hold near its top or bottom edge. On phones, tapping a day in the month view opens it in the day view.

### Keyboard

| Key | Action |
| --- | --- |
| `M` `W` `D` `A` | Month, week, day, agenda |
| `T` | Today |
| `←` `→` | Previous / next period |
| `N` | New event |
| `Enter` on an event | Edit it |

Shortcuts are ignored while typing or while any dialog is open.
