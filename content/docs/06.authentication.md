Every event belongs to one account. Sessions are sealed cookies (nuxt-auth-utils), so there is no session table; the
key that seals them is derived from `NUXT_APP_SECRET`.

## Passkeys

A passkey signs you in with your fingerprint, face, screen lock or a security key. Only its public key is stored, so
there's nothing to leak or phish.

- **Create an account with a passkey.** On the sign-in page choose **Create account**, enter your name and email, and
  confirm with your device. No password is set.
- **Sign in with a passkey.** Choose **Sign in with a passkey** — no email needed — or pick a passkey from the email
  field's autofill menu, where the browser supports it.
- **Manage passkeys** on the [Account](/account) page: add one per device or password manager, rename them, and remove
  ones you no longer use. The page shows when each was added and last used, and whether it syncs between devices.

An account always keeps a way in: you can't remove your only passkey unless you've also set a password.

::callout{type="warning"}
Passkeys are bound to the site's domain and need HTTPS (or `localhost`). Behind a reverse proxy, forward the original
`Host` and `X-Forwarded-Proto` headers so the server sees the public URL. Changing the domain later makes existing
passkeys unusable; people can then sign in with a password or create a new passkey.
::

## Passwords

Passwords (at least 8 characters) are stored as scrypt hashes. Accounts created with a passkey can set a password
later from the Account page as a backup; changing a password requires the current one. Wrong credentials and unknown
accounts get the same error, so the sign-in form doesn't reveal who has an account.

## Who can register

| Mode | How it works |
| --- | --- |
| **Bootstrap** | On an empty database the first account registers freely and becomes the admin. |
| **Invite-only** (default) | After that, registering needs an invite. Signed-in users create invite links on the Account page — optionally for one email address, valid for 1 to 30 days, usable once. |
| **Open** | `NUXT_OPEN_REGISTRATION=true` lets anyone register. |

The same rules apply to password and passkey sign-up. An invite link (`/login?invite=…`) opens the sign-up form with the
code filled in.

## Demo account

With `NUXT_DEMO_ENABLED=true` the sign-in page offers **Explore the demo**: a shared account with sample events around
today, reset every day at midnight. Its password and passkeys can't be changed, and it never counts towards bootstrap.

## Server-side checks

- Every `/api/events` route requires a session (401 otherwise); events are listed only for their owner.
- Updates and deletes go through `nuxt-authorization` abilities: someone else's event returns 403.
- WebAuthn challenges are single use, expire after five minutes, and are stored in the database so any server
  instance can verify them.
