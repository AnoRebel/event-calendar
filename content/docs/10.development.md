## Project layout

| Path | Contents |
| --- | --- |
| `app/registry/event-calendar/` | The calendar component — the registry's source of truth, also used by the app |
| `app/registry/event-calendar-*` | The optional registry layers (data, persistence, realtime) |
| `app/pages/` | Calendar (`index`), sign-in, account and docs pages |
| `app/components/app/` | App chrome: top bar, tab bar, user menu, Appearance dialog |
| `app/components/ui/` | shadcn-vue primitives, restyled with Crystal Neuo |
| `app/assets/crystal-neuo/`, `app/lib/crystal-neuo/` | Vendored Crystal Neuo CSS and runtime |
| `server/api/` | REST endpoints · `server/db/` schema and migrations · `server/utils/` shared server code |
| `shared/` | valibot schemas and abilities used by both client and server |
| `content/docs/` | These docs |
| `openspec/` | Specifications and change proposals |

## Conventions

- Dates: `date-fns` and `@date-fns/tz`.
- Forms: TanStack Form with valibot schemas; the server validates with the same schemas through `nuxt/server`.
- Server state: TanStack Query. Utilities: VueUse.
- Server code imports from `nuxt/server` (Nuxt 4.6's server API).
- The calendar component only uses shadcn-vue theme variables, so it stays portable.

## Scripts

| Script | Does |
| --- | --- |
| `bun run dev` | Dev server |
| `bun run build` / `bun run preview` | Production build / run it |
| `bun run typecheck` | `vue-tsc` across the app, server and shared code |
| `bun run lint` | ESLint |
| `bun run test:run` | Unit tests (Vitest) |
| `bun run test:e2e` | End-to-end tests (bunwright, see below) |
| `bun run db:generate` / `db:migrate` / `db:studio` | Drizzle migrations and studio |
| `bun run registry:build` | Compile the registry to `public/r/*.json` (`REGISTRY_HOST` sets the URL) |
| `bun run design:sync` | Re-vendor Crystal Neuo from `CRYSTAL_NEUO_DIR` |
| `bun run icons:generate` | Render the PWA icons from `public/icon.svg` |

## Tests

**Unit tests** cover the calendar's time-grid maths (positions, overlaps, drops, resizing), timezone conversion, event
status and colours:

```bash
bun run test:run
```

**End-to-end tests** drive a real Chromium-family browser with [bunwright](https://www.npmjs.com/package/bunwright) under
`bun test`. They build and start the app if nothing is running at `BASE_URL`, then cover sign-up and sign-in (including
passkeys through a virtual authenticator), the event lifecycle, drag and drop, the Appearance dialog and the phone
layout:

```bash
BUN_CHROME_PATH=/usr/bin/chromium bun run test:e2e
```

`BUN_CHROME_PATH` can point at Chromium, Chrome, Brave or Helium; without it the first one found is used.
