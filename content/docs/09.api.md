---
title: REST API
navTitle: REST API
description: The HTTP endpoints behind the app. All of them use the session cookie; none accept cross-origin requests.
---

Requests and responses are JSON. Errors have the shape `{ "statusCode": 400, "message": "…" }`; validation errors put
the first problem in `message`.

## Events

| Method | Path | Body / query | Response |
| --- | --- | --- | --- |
| `GET` | `/api/events` | `start`, `end` (ISO; returns events overlapping the range), `page`, `limit` (≤ 500) | `{ data, total, page, limit, hasMore }` |
| `POST` | `/api/events` | An event (see below) | `201` with the stored event and its server id |
| `PATCH` | `/api/events/:id` | Any event fields | The updated event |
| `DELETE` | `/api/events/:id` | — | `204` |

Unauthenticated requests get `401`; another user's event gets `403`; unknown ids get `404`.

```json
{
  "title": "Design review",
  "startDate": "2026-11-03T14:00:00.000Z",
  "endDate": "2026-11-03T15:00:00.000Z",
  "allDay": false,
  "color": "violet",
  "location": "Studio",
  "status": "confirmed",
  "timezone": "Europe/Berlin"
}
```

`title` is required, `endDate` must be after `startDate` (unless `allDay`), and unknown fields are ignored.
`isRecurring` is rejected with `403` while recurring events are turned off.

## Authentication

| Method | Path | Body | Notes |
| --- | --- | --- | --- |
| `GET` | `/api/auth/status` | — | `{ needsBootstrap, openRegistration, demoEnabled }` — public |
| `POST` | `/api/auth/register` | `{ email, password, name?, inviteToken? }` | Creates a password account and signs in |
| `POST` | `/api/auth/login` | `{ email, password }` | `401` for any wrong combination |
| `POST` | `/api/auth/logout` | — | Clears the session |
| `POST` | `/api/auth/demo` | — | Signs in to the demo account (when enabled) |
| `GET` | `/api/_auth/session` | — | The current session (nuxt-auth-utils) |
| `POST` | `/api/webauthn/register` | WebAuthn registration ceremony | Signed out: creates a passkey account. Signed in: adds a passkey. |
| `POST` | `/api/webauthn/authenticate` | WebAuthn authentication ceremony | Signs in with a discoverable passkey |

The WebAuthn endpoints are called twice per ceremony (`verify: false` for options, then `verify: true` with the
browser's response); `@simplewebauthn/browser` or nuxt-auth-utils' `useWebAuthn()` handle that for you.

## Account and invites

| Method | Path | Body | Response |
| --- | --- | --- | --- |
| `GET` | `/api/account` | — | Profile, `hasPassword`, and passkeys (`id`, `name`, `backedUp`, `createdAt`, `lastUsedAt`) |
| `PATCH` | `/api/account` | `{ name }` | Updated name |
| `PUT` | `/api/account/password` | `{ currentPassword?, newPassword }` | Sets or changes the password |
| `PATCH` | `/api/account/passkeys/:id` | `{ name }` | Renames a passkey |
| `DELETE` | `/api/account/passkeys/:id` | — | `204`, or `409` if it's the last way to sign in |
| `GET` | `/api/invites` | — | Your invites with `status`: `active`, `used` or `expired` |
| `POST` | `/api/invites` | `{ email?, expiresInDays? }` (1–90, default 14) | `201` with the token |
| `DELETE` | `/api/invites/:token` | — | Revokes an unused invite |

## Other

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/health` | Database probe; `503` when unreachable |
| `WS` | `/_ws` | Real-time event changes for the signed-in user (when collaboration is on) |
