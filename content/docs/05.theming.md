The app is built on [Crystal Neuo](https://crystal-neuo.anorebel.net), an adaptive design system with four independent
axes, each set as an attribute on `<html>` (or any element, where the nearest one wins):

| Axis | Values | Changes |
| --- | --- | --- |
| Material | `refraction` (default), `tactile`, `signal`, `folio`, `bloom`, `hybrid` | Palette, radii, borders, shadows, glass, type faces, motion |
| Platform | `web`, `ios`, `android`, `windows`, `macos` | UI font, control heights, corner scale, focus ring, touch targets |
| Theme | `light`, `dark`, `high-contrast` (or follow the system) | Which of the material's palettes is used |
| Density | `compact`, `comfortable`, `spacious` | Spacing and control heights |

## The Appearance dialog

Open it from the palette button in the top bar (or **Appearance** in the account menu). It sets every axis plus the
glass options — frost, rim light, live refraction (Chromium only) and reduced transparency. Each material card is drawn
in its own material, so you see the choice before you make it. **Match this device** picks the platform style from your
device.

Choices are saved in the browser and applied by a small inline script before the page paints, so there's no flash of
the default look. The moon/sun button in the top bar flips between light and dark.

Accessibility settings always win: reduced motion stops animation and refraction, reduced transparency (from the OS or
the dialog) makes glass opaque, and high contrast and forced colours use their own palettes.

## How the app wires it up

- `app/assets/crystal-neuo/` holds Crystal Neuo's tokens, base and component CSS; `app/lib/crystal-neuo/` holds its
  runtime. They are vendored because Crystal Neuo isn't published to npm. To upgrade:

  ```bash
  git clone https://github.com/AnoRebel/crystal-neuo ../crystal-neuo
  (cd ../crystal-neuo && bun install && bun run build:tokens)
  CRYSTAL_NEUO_DIR=../crystal-neuo bun run design:sync
  ```

- `app/assets/css/main.css` maps shadcn-vue's variables (`--background`, `--primary`, `--border`…) onto Crystal Neuo's
  semantic tokens, so every shadcn primitive — and the calendar — follows the active material.
- Buttons, inputs and selects render Crystal Neuo's own `cn-button` and `cn-input` classes, so each material's press,
  border and shadow behaviour carries over. Reka UI still provides the accessible behaviour.
- `useAppearance()` exposes the current axes as reactive state with setters.

## Theming the calendar in your project

The registry calendar only uses shadcn-vue's theme variables (`bg-card`, `text-muted-foreground`, `border`, `ring`…),
so it adopts whatever theme your project has, including its dark mode. Event colours are standard Tailwind palettes.

To use Crystal Neuo in your own project, import its CSS and point the shadcn variables at its tokens:

```css [main.css]
@import "tailwindcss";
@import "./crystal-neuo/tokens.css";
@import "./crystal-neuo/base.css" layer(base);
@import "./crystal-neuo/components.css" layer(components);

@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *, [data-theme="high-contrast"], [data-theme="high-contrast"] *));

:root, [data-material], [data-theme], [data-platform], [data-density] {
  --background: var(--surface-app);
  --foreground: var(--content-primary);
  --card: var(--surface-raised);
  --card-foreground: var(--content-primary);
  --popover: var(--surface-overlay);
  --popover-foreground: var(--content-primary);
  --primary: var(--accent-primary-base);
  --primary-foreground: var(--content-on-accent);
  --secondary: var(--surface-raised-2);
  --secondary-foreground: var(--content-primary);
  --muted: var(--surface-raised-1);
  --muted-foreground: var(--content-secondary);
  --accent: var(--accent-primary-soft);
  --accent-foreground: var(--content-primary);
  --destructive: var(--state-danger-strong);
  --border: var(--border-default);
  --input: var(--border-default);
  --ring: var(--focus-ring);
}
```

Base and component CSS go in cascade layers so Tailwind utilities still win; tokens stay unlayered so they override
Tailwind's defaults for shared names such as `--radius-md`. The variables are declared on every axis attribute so a
subtree with its own `data-material` re-resolves them.
